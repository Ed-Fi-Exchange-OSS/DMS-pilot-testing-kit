# Proposed Pilot Test of SIS Integration with Ed-Fi API v8

## Purpose

The purpose of this pilot is to validate the operational readiness, conformance,
and performance of the Ed-Fi API v8 platform by processing data from a
production-grade Student Information System (SIS) vendor environment. While the
platform has undergone extensive internal testing, additional confidence can be
gained by executing a controlled pilot using data generated by an independent
SIS implementation.

## Scope

Participating SIS vendors will be provided with:

- A preconfigured deployment package based on Docker Compose, configured with
  Ed-Fi Data Standard 5.2.
- Associated configuration and setup scripts.
- Documentation sufficient to enable installation and initial operation within a
  short period of time, with a goal of requiring less than one hour of setup
  effort.

The pilot will ask vendors to:

- Deploy the provided environment in a non-production testing environment.
- Submit representative SIS-generated data to the Ed-Fi API v8 platform.
- Report any installation, configuration, interoperability, or data-processing
  issues encountered during testing.

## Evaluation Criteria

Where feasible, testing results will be collected through automated scripts and
logs. Metrics of interest include:

- Error counts generated during processing.
- Successfully processed or landed record counts.
- End-to-end processing duration, measured from the first inbound request to
  completion of data transmission.

## Comparative Testing

As an optional activity, vendors may also execute the same data feed against a
current Ed-Fi ODS/API implementation. Comparative results would help assess
behavioral consistency, performance characteristics, and readiness for migration
to the new platform.

## Desired Outcomes

The pilot is intended to:

- Demonstrate successful interoperability between SIS vendor products and the
  Ed-Fi API v8 platform.
- Validate deployment and onboarding processes for external implementers.
- Identify integration, usability, or operational issues prior to broader market
  adoption.
- Generate real-world evidence of product readiness that can inform future
  release planning and community guidance.

## Participation Expectations

Participating vendors are asked to contribute feedback on installation
experience, configuration requirements, data processing outcomes, and overall
usability. This feedback will be used to improve documentation, deployment
automation, and product quality prior to general
availability.
