# pgAdmin

`servers.json` pre-registers the kit's PostgreSQL server in pgAdmin (NFR-OBS-2). There is one
entry, **Ed-Fi API v8 (DMS + CMS)**, in group **Ed-Fi Pilot Kit**, which connects to host `db`
port 5432 as `postgres`. The DMS and CMS databases both live on that server. No password is
stored. pgAdmin prompts for it, and the value is `POSTGRES_PASSWORD` from `.env`.

pgAdmin is reached only through the ingress at `https://<host>/pgadmin/`. It publishes no port.


## Required environment for the `pgadmin` service

| Variable | Value | Why |
| --- | --- | --- |
| `SCRIPT_NAME` | `/pgadmin` | pgAdmin generates all links under `/pgadmin`. Must match the ingress route. |
| `PGADMIN_DEFAULT_EMAIL` | from `.env`, for example `admin@example.com` | Initial login. **Local development only.** pgAdmin validates the address and rejects special-use domains such as `.local` and `.localhost`. |
| `PGADMIN_DEFAULT_PASSWORD` | from `.env`, generated by the start script | Initial login. **Local development only.** Read only on first launch, when the `pgadmin-data` volume is empty. |
| `PGADMIN_CONFIG_SERVER_MODE` | `True` (recommended) | Server mode requires the login above. `False` (desktop mode) skips the login entirely, which is simpler but leaves the UI open to anyone who can reach `127.0.0.1`. |
| `PGADMIN_REPLACE_SERVERS_ON_STARTUP` | `True` | `servers.json` is otherwise imported only on first launch. This keeps it authoritative across restarts with a persisted volume. |
| `PGADMIN_CONFIG_UPGRADE_CHECK_ENABLED` | `False` | Stops pgAdmin from calling home for version checks (NFR-SEC-6, no unexpected outbound traffic). |
| `PGADMIN_DISABLE_POSTFIX` | `true` | No mail server is needed; this avoids starting Postfix through sudo. |
| `PGADMIN_LISTEN_PORT` | `80` (the default) | Stated explicitly because the entrypoint silently switches to `8080` under `security_opt: no-new-privileges` or `cap_drop: [ALL]`. If the kit hardens the container that way, set `8080` here **and** in the ingress. |

`PGADMIN_CONFIG_*` values use Python literal syntax: `True`/`False` unquoted, and strings in single
quotes, for example `PGADMIN_CONFIG_LOGIN_BANNER: "'Local pilot kit only'"`.

### Compose service sketch (for `compose.yml`)

```yaml
  pgadmin:
    image: ${PGADMIN_IMAGE}
    environment:
      SCRIPT_NAME: /pgadmin
      PGADMIN_DEFAULT_EMAIL: ${PGADMIN_DEFAULT_EMAIL}
      PGADMIN_DEFAULT_PASSWORD: ${PGADMIN_DEFAULT_PASSWORD}
      PGADMIN_CONFIG_SERVER_MODE: "True"
      PGADMIN_REPLACE_SERVERS_ON_STARTUP: "True"
      PGADMIN_CONFIG_UPGRADE_CHECK_ENABLED: "False"
      PGADMIN_DISABLE_POSTFIX: "true"
      PGADMIN_LISTEN_PORT: "80"
    volumes:
      - pgadmin-data:/var/lib/pgadmin
      - ./pgadmin/servers.json:/pgadmin4/servers.json:ro
    depends_on:
      db:
        condition: service_healthy
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1:80/pgadmin/misc/ping || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 12
      start_period: 30s
    # No ports: reachable only through the ingress at /pgadmin/.
```

`/misc/ping` is pgAdmin's unauthenticated liveness endpoint. With `SCRIPT_NAME` set, it's served
under the prefix. The container runs as UID 5050, so `servers.json` must be world-readable on the
host. A normal git checkout satisfies that.

## Ingress requirements (NGINX `default.conf.template`)

With `SCRIPT_NAME=/pgadmin`, forward the **full path, without stripping the prefix**. Use no URI
on `proxy_pass`:

```nginx
location = /pgadmin { return 301 /pgadmin/; }
location /pgadmin/ {
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Port $server_port;
    proxy_redirect off;
    proxy_pass http://pgadmin:80;
}
```

pgAdmin trusts one hop of `X-Forwarded-For`, `-Proto`, and `-Port` by default
(`PROXY_X_*_COUNT = 1`), so redirects stay on `https`. The alternative pgAdmin documents, a
stripping `proxy_pass http://pgadmin:80/;` plus `proxy_set_header X-Script-Name /pgadmin;`, also
works. Use one approach, not both.
